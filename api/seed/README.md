# 개발 시드

`yarn seed:dev`가 쓰는 파일들이에요. 개발 전용이라 서버 빌드(`yarn build`)에는 들어가지 않아요.

- `lib/`: 시드 로직과 그 단위 테스트.
- `mock/`: 화면용 목업 묶음(자세한 설명은 `mock/README.md`).
- `dev-project.json`: 개발용 Supabase 프로젝트의 ref. `seed:dev`는 `NODE_ENV=development`이고 `SUPABASE_URL`의 프로젝트 ref가 이 값과 같을 때만 실행돼요. 프로젝트 ref는 `https://<ref>.supabase.co` 주소에 드러나는 공개 값이라 비밀이 아니에요. 개발 프로젝트를 새로 만들면 이 파일의 값을 바꿔 주세요.

## `yarn seed:dev`가 만드는 것

1. 개발 계정 7개(Supabase Auth + `users` 행). 010-0000-0001 가게, 0002 브랜드, 0003 크리에이터 `서윤의 작은 취향`, 0004~0007 목업 크리에이터(`하루 한 컵`, `성수 한 끼`, `면치기 일기`, `민의 옷장 기록`). 인증번호는 모두 000000이에요.
2. 크리에이터 프로필 5개(0003~0007). 사진이 있는 사람은 개발 프로젝트의 `photos` 버킷 `creators/<userId>/seed-profile.<ext>`에 올려요.
3. 0001의 가게 `한그릇 라멘`(공개 상태, 기본 조건 릴스 + 식사권 + 조회수, 출처 링크 둘). 사진은 `stores/<userId>/seed-cover.png`예요. 콘텐츠 초안은 만들지 않아요(처음 읽을 때 가짜 어댑터가 만들어요).
4. 0001 가게에 지원 3건(하루 한 컵 오늘, 성수 한 끼 어제, 면치기 일기 2일 전)과 민의 옷장 기록에게 보낸 오퍼 1건(거절됨). 0003에게는 아무것도 만들지 않아요(시연에서 직접 지원·오퍼를 해 보려고요).

여러 번 돌려도 같은 결과예요. 돌릴 때마다 0001 가게의 지원·오퍼와 목업 크리에이터(0003~0007)의 지원·오퍼를 지우고 위 상태로 다시 만들어요. **그래서 시연 중에 0001이나 0003이 만든 지원·오퍼도 시드를 다시 돌리면 사라져요.** 다른 계정의 행은 건드리지 않아요.
