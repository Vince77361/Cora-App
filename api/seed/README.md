# 개발 시드

`yarn seed:dev`가 쓰는 파일들이에요. 개발 전용이라 서버 빌드(`yarn build`)에는 들어가지 않아요.

- `lib/`: 시드 로직과 그 단위 테스트.
- `mock/`: 화면용 목업 묶음(자세한 설명은 `mock/README.md`).
- `dev-project.json`: 개발용 Supabase 프로젝트의 ref. `seed:dev`는 `NODE_ENV=development`이고 `SUPABASE_URL`의 프로젝트 ref가 이 값과 같을 때만 실행돼요. 프로젝트 ref는 `https://<ref>.supabase.co` 주소에 드러나는 공개 값이라 비밀이 아니에요. 개발 프로젝트를 새로 만들면 이 파일의 값을 바꿔 주세요.

## `yarn seed:dev`가 만드는 것

1. 개발 계정 7개(Supabase Auth + `users` 행). 010-0000-0001 가게, 0002 브랜드, 0003 크리에이터 `서윤의 작은 취향`, 0004~0007 목업 크리에이터(`하루 한 컵`, `성수 한 끼`, `면치기 일기`, `민의 옷장 기록`). 인증번호는 모두 000000이에요.
2. 크리에이터 프로필 5개(0003~0007). 사진이 있는 사람은 개발 프로젝트의 `photos` 버킷 `creators/<userId>/seed-profile.<ext>`에 올려요.
3. 0001의 가게 `한그릇 라멘`(공개 상태). 모집 조건은 릴스 + 식사권 40,000원·2인 + 1,000회당 2,000원(상한 60,000원)이고 사용권은 재게시 3개월이에요. 공개 주소 이름은 `hangeureut-ramen`, 꼬리표(`진한국물` `바좌석` `조용한오후`)와 손님들이 자주 한 말, 모집 한 줄 `첫 숟가락 릴스`, 체험단 정보(월 300,000원, 석 달 글 9개, 종료일은 **시드를 돌린 날의 한국 날짜 + 28일**)가 들어가요. 출처 링크는 네이버 지도, 캐치테이블, 인스타그램 셋이에요. 사진은 `stores/<userId>/seed-cover.png`예요. 콘텐츠 초안은 만들지 않아요(처음 읽을 때 가짜 어댑터가 만들어요).
4. 지원자 5명(하루 한 컵 오늘, 성수 한 끼 어제, 면치기 일기 2일 전, 민의 옷장 기록 3일 전, 서윤의 작은 취향 4일 전). 하루 한 컵·민·서윤은 한 줄(G2 캔버스의 세 문장)이 있어요.
5. 제안함(0001 기준): **내가 응답할 차례** 1건(하루 한 컵이 카드뉴스 1편으로 고쳐 보낸 판본 2), **상대 대기** 2건(민, 서윤 — 판본 1), **종료** 2건(합의 완료 1: 아래 협업의 오퍼, `일정이 맞지 않아 종료` 1: 서윤). 제안은 지원과 이어 두지 않아서, 지원자 5명은 그대로 지원 중으로 보여요.
6. 정산이 끝난 협업 1건(하루 한 컵, 릴스, 12,500회 → 크리에이터 지급 25,000원, 사장님 환불 35,000원, 평소 4,000회의 3.1배). 결제 승인과 정산의 장부 줄이 들어 있고 에스크로 잔액은 0이에요. 정산을 열흘 전으로 두어 지급·환급 행은 끝난 상태예요.
7. 0003 크리에이터에게 시리즈 3개(`한 그릇 일기`, `동네 점심 지도`, `소리로 먹는 집`, F6 캔버스).

여러 번 돌려도 같은 결과예요. 돌릴 때마다 0001 가게와 목업 크리에이터(0003~0007)의 지원·제안(과 그 제안에 붙은 협업·결제·장부·지급·환급 행)과 목업 크리에이터의 시리즈를 지우고 위 상태로 다시 만들어요. **그래서 시연 중에 0001이나 0003이 만든 지원·제안·시리즈도 시드를 다시 돌리면 사라져요.** 다른 계정의 행(0041 이후 시험 계정 포함)과 위 제안에 붙지 않은 협업은 건드리지 않아요. 날짜는 돌린 날을 기준으로 며칠 전·후로 정해서, 돌린 날에 따라 날짜 글자는 달라져요.
