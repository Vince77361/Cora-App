## 1. 무엇을, 왜

계약이 맺어진 브랜드 협업에서, 크리에이터가 기획 방향을 저장하고, 초안 영상을 올려 브랜드와 구간별 댓글로 검토하고, 게시한 뒤 혼자만 보는 회고를 남긴다. 회고와 무산된 상대는 보관함에 모여 다음 협업으로 이어진다.

- **[화면]** "정보는 정확하게, 표현은 나답게." 브랜드가 정하는 것과 크리에이터가 정하는 것을 나눈다.
- **[화면]** "상대에게 보이지 않는 회고." 회고는 평점이 아니라 본인을 위한 기록이다.

### 적용 범위

- **[제안]** 이 설계의 기획 가이드와 초안 검토는 브랜드 계약에서 온 협업에만 적용한다. 가게 오퍼는 방문 → 게시 → 링크 제출로 끝난다(3번 설계). 회고와 보관함은 두 종류 모두에 적용한다.

### 하지 않는 것

- 앱 안에서 영상을 편집하거나 자르기
- 상대에게 공개되는 후기와 별점
- 초안 영상의 화질 변환

### 실패로 보는 것

- 회고가 상대에게 보이는 것
- 광고 표시를 확인하지 않았는데 초안이 확정되는 것
- 초안 영상이 협업 당사자가 아닌 사람에게 보이는 것

## 2. 화면별 동작

### 13 기획 가이드 (크리에이터)

- **[화면]** 콘텐츠 제목, "정보는 정확하게, 표현은 나답게." 두 열의 표:

| 브랜드가 정해요 | 내가 정해요 |
|---|---|
| 제품 소재와 관리 방법 | 도입부와 이야기 흐름 |
| 제품명·브랜드명 정확히 | 촬영 장소·구도·음악 |
| 광고 관계 표시 | 평소 말투와 솔직한 후기 |
| 확인 안 된 효능 표현 빼기 | 얼굴 없이 손 중심 촬영 |

- **[화면]** "장면 흐름 제안": 장면 세 개(예: 세안, 옷 고르기, 주얼리 착용). "이 방향으로 저장".
- **[제안]** 왼쪽 열은 캠페인의 "꼭 담을 것"에 고정 두 줄("광고 관계 표시", "확인 안 된 효능 표현 빼기")을 더한 것이다. 오른쪽 열은 크리에이터의 협업 원칙에서 만든다(얼굴 출연, 대본, 솔직 후기)에 고정 두 줄("도입부와 이야기 흐름", "촬영 장소·구도·음악")을 더한다.
- **[제안]** 장면 흐름은 `ContentDraftPort`(2번 설계의 AI 초안 포트)로 만든다. 크리에이터가 장면 이름을 고치거나 순서를 바꾸거나 최대 5개까지 더할 수 있다.
- **[제안]** "이 방향으로 저장"하면 브랜드에게 알림이 가고 브랜드는 같은 화면을 읽기 전용으로 본다. 브랜드의 승인 단계는 두지 않는다. 의견은 대화로 한다. 저장하면 진행 단계가 4단계 "기획안 검토·제작"이 된다.

### 14 초안 검토 (양쪽)

- **[화면]** "초안 v2 검토", 영상, 재생 막대 위에 댓글 표시, 고른 댓글의 시각·작성자·내용, 댓글 목록, 입력란 "{시각} 구간에 댓글 남기기", 스위치 "광고 표시를 확인했어요", "초안 확인 완료".
- **[제안]** 크리에이터가 초안 영상을 올리면 v1이 된다. 다시 올리면 v2, v3이 되고 이전 버전과 그 댓글은 남는다. 올릴 수 있는 횟수는 합의한 "수정 범위"보다 하나 많다(초안 기준 1회 수정이면 v2까지). 그 뒤에는 "합의한 수정 횟수를 다 썼어요. 더 고치려면 브랜드가 수정을 허용해야 해요." 수정 범위별 횟수와 "수정 한 번 더 허용"은 공통 규칙 7장에 있다.
- **[제안]** 댓글은 영상을 멈춘 시각에 달린다. 양쪽 모두 달 수 있다. 댓글을 누르면 영상이 그 시각으로 간다. 한 개에 300자.
- **[제안]** "광고 표시를 확인했어요"는 브랜드와 크리에이터가 각자 켠다. 둘 다 켜야 브랜드의 "초안 확인 완료"가 눌린다. 이 버튼은 브랜드에게만 있다. 크리에이터에게는 "브랜드의 확인을 기다리고 있어요."
- **[제안]** 확인이 끝나면 크리에이터에게 "초안이 확정됐어요. 게시하고 링크를 제출해 주세요." 링크 제출은 3번 설계의 화면을 쓴다. 진행 단계는 6단계 "게시·성과 확인"이 된다.
- **[제안]** 영상: 길이 3분, 크기 300MB까지, MP4와 MOV. 화면은 올리는 중 진행률을 보여 주고, 끊기면 이어 올린다.
- **[제안]** 형식이 카드뉴스나 블로그 글이면 영상 대신 사진 여러 장(최대 10장)을 올리고, 댓글은 시각 대신 "몇 번째 장"에 달린다.

### 15 회고·재협업

- **[화면]** "상대에게 보이지 않는 회고", 상대 이름, "게시 완료".
- **[화면]** "잘 맞았던 점" 여러 개 고르기: 촬영 방식의 자유, 빠른 피드백, 정확한 제품 정보, 정산 약속.
- **[화면]** "다음엔 바꾸고 싶은 점" 여러 개 고르기: 배송 기간, 제품 사용 기간, 수정 횟수, 소통 속도.
- **[화면]** "다음에 가능한 날", "다음 희망 제작비", "이 브랜드와 다시 만날래요?" → "이번만 할래요" / "다시 만날래요". "어느 쪽을 골라도 회고는 나만 볼 수 있게 저장돼요."
- **[제안]** 캔버스는 크리에이터의 회고다. 브랜드와 사장님도 같은 구성의 회고를 쓴다. 고르는 항목만 다르다: 잘 맞았던 점(콘텐츠 완성도, 일정 준수, 소통, 브랜드 이해), 바꾸고 싶은 점(일정, 수정 과정, 소통 속도, 조건).
- **[제안]** 회고는 정산이 끝나면 쓸 수 있고, 쓰지 않아도 된다. 협업 화면에 "회고 남기기"가 생긴다. 나중에 고칠 수 있다.
- **[제안]** "다시 만날래요"를 고르면 그 상대가 보관함에 들어간다. "이번만 할래요"도 회고는 저장되지만 보관함의 "완료한 협업"에만 보인다.

### D5 보관함 — 다시 만나고 싶은 상대

- **[화면]** "보관함", "다시 만나고 싶은 브랜드", "일정이나 예산 때문에 무산된 상대도 여기에 남아요." 탭: 전체, 완료한 협업, 무산된 상대. 줄마다 이름, 상태(예: "협업 완료, 비공개 회고 저장됨", "일정이 맞지 않아 무산"), 가능한 날, 희망 제작비, "재협업 메시지 만들기".
- **[제안]** "무산된 상대"는 서로 관심까지 갔거나 조건을 주고받았지만 계약에 이르지 못한 협업이다. 협의를 그만둘 때 사유를 하나 고르게 한다: 일정이 맞지 않아요, 예산이 맞지 않아요, 방향이 달라요, 기타. 이 사유가 상태 문구가 된다. 사유는 상대에게 "이번에는 함께하기 어렵대요."로만 전해진다.
- **[제안]** "협의 그만두기"는 조건 합의 화면과 대화방 메뉴에 둔다. 계약 체결 뒤에는 누를 수 없고 "문의하기"로 안내한다.
- **[제안]** 가능한 날과 희망 제작비는 회고에서 온다. 무산된 상대는 이 두 값을 보관함에서 직접 넣을 수 있다.
- **[제안]** "재협업 메시지 만들기"는 `ContentDraftPort`로 인사 글 초안을 만들어 그 상대와의 대화방 입력란에 넣는다. 보내기는 본인이 누른다. 대화방이 차단돼 있으면 버튼이 꺼진다.
- **[제안]** 보관함은 프로필 탭 안에 있다. 브랜드와 사장님 쪽의 제목은 "다시 만나고 싶은 크리에이터"다.
- **[제안]** 체결된 계약도 보관함의 각 줄에서 "계약 보기"로 열 수 있다(5번 설계의 "계약서는 체결 후 보관함에 저장돼요").

## 3. 협업 상태의 전체 그림

4, 5, 6번 설계를 합친 브랜드 협업의 진행이다. 07 진행 단계 화면이 이 순서를 보여 준다.

| 단계(07 화면) | 넘어가는 조건 | 설계 |
|---|---|---|
| 1 서로 관심 확인 | 양쪽이 관심을 보냄 | 4번 |
| 2 조건 검토 의사 표시 | "이 조건으로 협의" 또는 수정 제안 | 4번, 5번 |
| 3 양쪽 조건 확정·계약 | 같은 버전 확인 → 양쪽 동의, 브랜드 결제 | 5번 |
| 4 기획안 검토·제작 | 기획 방향 저장 | 6번 |
| 5 광고 표시·초안 검토 | 초안 올림 → 브랜드의 초안 확인 완료 | 6번 |
| 6 게시·성과 확인 | 링크 제출 → 지급 | 3번, 6번 |

끝나는 길: 완료(지급 끝), 무산(계약 전에 그만둠), 중단(계약 뒤 문제가 생겨 운영자가 처리).

- **[제안]** 계약 뒤에 생긴 문제(크리에이터가 초안을 올리지 않음, 브랜드가 확인하지 않음)는 자동으로 처리하지 않는다. 기한 알림만 보내고, 당사자가 "문의하기"로 운영자에게 알린다. 운영자는 공통 규칙 2장의 운영 명령으로 처리한다(DB를 직접 고치지 않는다).
- **[제안]** 기한 알림: 제작 시작일에서 14일이 지나도 초안이 없으면 크리에이터에게, 초안을 올린 지 3일이 지나도 브랜드의 반응이 없으면 브랜드에게 알린다.

## 4. 데이터와 서버 (윤곽)

| 테이블 | 담는 것 |
|---|---|
| `production_guides` | 협업, 브랜드가 정하는 것 목록, 내가 정하는 것 목록, 장면 목록, 저장 시각 |
| `draft_versions` | 협업, 버전 번호, 파일 경로 목록, 종류(영상·사진), 길이, 올린 시각 |
| `draft_comments` | 초안 버전, 작성자, 위치(초 또는 장 번호), 내용 |
| `draft_approvals` | 초안 버전, 크리에이터의 광고 표시 확인, 브랜드의 광고 표시 확인, 브랜드의 확인 완료 시각 |
| `retrospectives` | 협업, 작성자, 잘 맞은 점, 바꾸고 싶은 점, 다음 가능한 날, 다음 희망 제작비, 다시 만날지 |
| `keep_entries` | 주인, 상대, 연결된 협업, 종류(완료·무산), 무산 사유, 가능한 날, 희망 제작비 |

### 파일

- 초안 영상과 사진은 Supabase Storage의 비공개 버킷에 둔다. 2번 설계의 공개 사진 버킷과 다른 버킷이다.
- 올릴 때는 서버가 발급한 이어 올리기 주소를 쓰고, 볼 때는 서버가 당사자에게만 짧게 유효한 주소(1시간)를 발급한다.
- **[제안]** 초안 파일은 협업이 끝난 뒤 90일이 지나면 지운다. 댓글과 기록은 남긴다.

### 권한

- 기획 가이드는 크리에이터만 고치고 양쪽이 읽는다.
- 초안은 크리에이터만 올리고, 댓글은 양쪽이 쓰고, 확인 완료는 브랜드만 한다.
- 회고와 보관함은 작성자 본인만 읽는다. 다른 사용자의 요청에는 그 존재도 드러내지 않는다(404). 상대에게 가는 어떤 응답에도 회고의 값을 넣지 않는다.

## 5. 소유자 확인이 필요한 것

1. **가게 오퍼에는 초안 검토가 없다.** 사장님이 게시 전에 초안을 보고 싶어 할지.
2. **기획 가이드에 브랜드 승인이 없다.** 저장하면 바로 제작 단계로 넘어가게 했다.
3. **브랜드와 사장님의 회고.** 캔버스에는 크리에이터의 회고만 있다. 같은 구성으로 만들었고 고르는 항목은 추측이다.
4. **초안 파일의 한도.** 3분, 300MB. Supabase Pro의 파일 크기 한도와 전송량 요금을 확인해야 한다.
5. **계약 뒤 문제의 처리.** 자동 처리 없이 운영자가 손으로 처리하게 했다.

## 6. 만드는 사람에게 맡기는 것

- 테이블의 정확한 컬럼, 엔드포인트
- 영상 재생기와 이어 올리기에 쓸 Flutter 패키지
- 댓글 표시가 겹칠 때의 표시 방식
- 수정 제안, 협의 그만두기, 보관함 편집 화면의 배치
