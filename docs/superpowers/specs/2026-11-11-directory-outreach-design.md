# 유입 전략: 외부 리스트 검색과 미가입 계정 연락 — 기능 설계

- 상태: 소유자 승인 (2026-11-11). 답이 없던 확인 항목은 제안과 9번 설계 9장의 기본 결정대로 진행한다.

표기: **[회의]** 회의 녹취에서 확인됨 · **[화면]** 기획 캔버스에서 확인됨 · **[제안]** 작성자의 추측이며 소유자 확인 전

## 1. 무엇을, 왜

가입한 크리에이터가 적은 초기에, 아직 가입하지 않은 인스타그램 계정까지 목록으로 보여 주고 사장님이 연락할 수 있게 한다. 연락을 받은 사람이 가입하면 그 오퍼가 바로 받은 오퍼에 들어온다.

- **[회의]** 가입한 사람만으로는 초반에 매칭이 어렵다. 목록을 갖고 있다가, 가입하지 않은 사람에게는 쪽지를 보내 가입하게 한다. 유입 전략이기도 하다.
- **[회의]** 다만 "허락을 받지 않고 하는 것은 어떻게 해야 될지 모르겠다", "좋은 방법인지 아직 잘 모르겠다"는 말이 함께 있었다. 확신이 없는 상태의 아이디어다.

## 2. 먼저 알아야 할 것: 캔버스대로는 실제로 만들기 어렵다

캔버스의 설계는 두 가지를 전제한다. 둘 다 실제 연동 단계에서 막힐 가능성이 높다. 법률·정책 사안이라 이 문서는 결론을 내리지 않지만, 설계는 막힐 것을 전제로 짰다.

| 캔버스의 전제 | 걸리는 것 |
|---|---|
| 인스타그램 공개 정보로 수십만 계정의 목록을 만들고 매주 갱신한다 | 인스타그램은 자동 수집을 약관으로 금지한다. 공식 API는 연결에 동의한 계정의 정보만 준다. 개인의 계정 정보를 동의 없이 모아 두는 것은 개인정보 보호 법규의 대상일 수 있다. |
| Cora 쪽지를 인스타그램 DM으로 대신 전달한다 | 공식 메시지 API는 상대가 먼저 말을 건 경우에만 답할 수 있다. 모르는 계정에 먼저 보내는 길이 없다. 영리 목적의 광고성 메시지를 사전 동의 없이 보내는 것은 정보통신망 관련 법규의 대상일 수 있다. |

그래서 이 설계는 화면과 서버를 포트 뒤에 만들되, **실제 구현의 기본안을 캔버스와 다르게** 잡는다.

- **목록의 출처(기본안).** 운영자가 손으로 고른 계정을 등록한다. 자동 수집은 하지 않는다.
- **연락의 방식(기본안).** Cora가 대신 보내지 않는다. 앱이 메시지와 초대 링크를 만들어 주고, 사장님이 자기 인스타그램 계정으로 직접 보낸다.

캔버스대로의 방식(자동 수집, 대신 전달)은 포트의 다른 구현으로 남겨 둔다. 허용된다는 확인을 받으면 구현을 바꿔 끼운다.

### 하지 않는 것

- 브랜드 목록 수집 (회의에서 언급됐지만 캔버스에 없다)
- 목록에 있는 사람에 대한 평가나 메모 기능

### 실패로 보는 것

- 수신을 거부한 계정이 목록에 다시 나오거나 다시 연락받는 것
- 같은 계정에 여러 사장님의 연락이 몰리는 것
- 초대 링크로 가입한 사람이 다른 사람에게 온 오퍼를 가져가는 것

## 3. 화면별 동작

### C1 외부 리스트 검색 (사장님)

- **[화면]** 위에 "릴스 / 리스트" 전환. "크리에이터 찾기", 검색란, 탭: 전체, 가입함, 미가입. 조건 표지 "팔로워 1천 – 5만". 안내 "인스타그램 공개 정보로 만든 목록이에요. 매주 일부씩 업데이트해요."
- **[화면]** 줄: 이름 첫 글자, 이름, "@noodle.diary, 팔로워 1.2만, 3일 전 업데이트" 또는 "@onecup.day, 팔로워 640, 가입함". 오른쪽 "가입함" 또는 "연락하기".
- **[제안]** 검색은 이름과 아이디에서 찾는다. 분야 꼬리표로도 거를 수 있다.
- **[제안]** "가입함" 줄을 누르면 7번 설계의 프로필(B5)로 가고 거기서 오퍼를 보낸다. "연락하기"는 C2로 간다.
- **[제안]** 안내 문구는 목록의 출처에 맞춘다. 기본안에서는 "Cora가 고른 크리에이터 목록이에요."
- **[제안]** 이미 연락한 계정은 "연락함"으로 보이고 다시 누를 수 없다.
- **[제안]** 사장님의 "찾기" 탭에서 릴스(7번)와 리스트를 전환한다.

### C2 미가입 계정에 연락

- **[화면]** "연락하기", 계정 이름, "@noodle.diary, 팔로워 1.2만", "아직 Cora 미가입". "보낼 메시지"에 미리 채워진 글(가게 소개, 상대의 콘텐츠를 봤다는 말, 보상, 링크 안내). 안내 세 줄: "Cora 쪽지로 보내면 인스타그램 DM으로 전달돼요.", "오퍼 조건과 가입 링크가 함께 가요.", "답이 오기 전에는 같은 계정에 다시 보낼 수 없어요. 상대가 수신을 거부하면 목록에서 빠져요." 버튼 "쪽지 보내기".
- **[제안]** 메시지 초안은 가게 이름, 동네, 기본 오퍼 조건으로 만든다. 사장님이 고칠 수 있다(300자까지).
- **[제안, 기본안]** 버튼은 "메시지 복사하고 인스타그램 열기"다. 누르면 메시지와 초대 링크가 복사되고 그 계정의 인스타그램 프로필이 열린다. 사장님이 직접 붙여 넣어 보낸다. 첫 안내 줄은 "메시지를 복사해 드려요. 인스타그램에서 직접 보내 주세요."로 바꾼다.
- **[제안]** 앱으로 돌아오면 "보내셨나요?"를 묻는다. "보냈어요"를 누르면 연락이 기록되고 사장님 홈의 보낸 오퍼에 "미가입, 쪽지 보냄"으로 나온다(2번 설계 A9의 그 줄).

### 초대 링크와 가입

- **[제안]** 초대 링크는 연락마다 하나씩 만든다. 링크를 열면 가게 이름과 오퍼 조건, "Cora에서 수락하기"가 있는 웹 페이지가 뜨고 앱 설치로 이어진다. 이 웹 페이지는 서버가 내려 주는 단순한 한 장이다.
- **[제안]** 링크로 들어와 가입한 사람이 크리에이터 프로필을 만들고 **그 인스타그램 계정을 연동하면**(7번 설계) 연락이 정식 오퍼로 바뀌어 받은 오퍼에 들어온다. 연동한 계정이 연락받은 계정과 다르면 바뀌지 않는다. 링크만으로는 오퍼를 가져갈 수 없다.
- **[제안]** 웹 페이지 아래에 "이런 연락을 받고 싶지 않아요"가 있다. 누르면 그 계정은 목록에서 빠지고 누구도 다시 연락할 수 없다.
- **[제안]** 연락은 14일 뒤 만료된다. 만료되면 사장님 쪽에 "답이 없었어요"로 보이고, 그 계정에는 30일 동안 누구도 다시 연락할 수 없다.

## 4. 규칙

- 한 계정에는 살아 있는 연락이 하나만 있을 수 있다(가게와 무관하게). 다른 사장님에게 그 계정은 "다른 가게가 연락 중"으로 보인다.
- **[제안]** 한 가게는 하루에 5건까지 연락할 수 있다.
- 수신 거부한 계정의 아이디는 거부 목록에 남긴다. 목록을 다시 채울 때 거부 목록에 있는 아이디는 넣지 않는다.
- 목록의 계정이 가입해 인스타그램을 연동하면 그 줄은 "가입함"이 되고 프로필과 이어진다.
- **[제안]** 목록에는 아이디, 표시 이름, 팔로워 수(대략), 분야 꼬리표만 둔다. 사진과 게시물은 저장하지 않는다.

## 5. 데이터와 서버 (윤곽)

| 테이블 | 담는 것 |
|---|---|
| `directory_accounts` | 인스타그램 아이디, 표시 이름, 팔로워 수, 분야 꼬리표, 마지막 갱신, 연결된 크리에이터(가입했으면) |
| `outreach_messages` | 가게, 대상 계정, 메시지, 오퍼 조건 사본, 초대 코드, 상태(준비·보냄·가입으로 전환·만료·거부), 보낸 시각 |
| `directory_opt_outs` | 인스타그램 아이디, 거부 시각 |

### 새 연동 포트

- `DirectoryPort`: 목록을 채우고 갱신한다. 가짜 구현은 캔버스의 견본 계정 여섯 개를 넣는다. 실제 구현의 기본안은 운영자가 올린 목록 파일을 읽는 것이다.
- `OutreachPort`: 연락을 전달한다. 구현이 두 가지다. "사장님이 직접 보냄"(기본안: 서버는 기록만 한다)과 "대신 전달"(캔버스의 방식). 환경변수 `OUTREACH_ADAPTER`의 값은 `fake`, `manual`, `relay`다.
- **[제안]** `manual`은 실제 구현으로 취급한다. 운영 환경에서 막는 것은 `fake`뿐이다.

### 권한

- 목록과 연락은 `STORE` 역할만 쓴다. 자기 가게의 연락만 읽는다.
- 초대 링크의 웹 페이지와 수신 거부는 로그인 없이 열린다. 초대 코드는 추측할 수 없는 긴 임의 값이고, 페이지에는 가게의 공개 정보와 오퍼 조건만 나온다.

## 6. 법적·정책 확인이 필요한 것

실제 구현 전에 반드시 확인한다. 이 문서는 결론을 내리지 않는다.

- 인스타그램 계정 정보를 본인 동의 없이 목록으로 보관하는 것 (운영자가 손으로 고른 경우 포함)
- 사장님이 앱의 도움으로 영리 목적의 메시지를 모르는 사람에게 보내는 것
- 인스타그램 약관상, 앱이 만들어 준 메시지를 이용자가 반복해 보내는 것이 스팸으로 취급되는지
- 수신 거부한 사람의 아이디를 거부 목록으로 계속 보관하는 것의 근거

## 7. 소유자 확인이 필요한 것

1. **이 기능을 첫 출시에 넣을지.** 전체 범위가 결정 사항이지만, 이 묶음만은 법적 확인 결과에 따라 빠질 수 있다. 다른 기능은 이 묶음에 의존하지 않도록 설계했다.
2. **기본안으로 갈지.** 자동 수집과 대신 전달을 포기하고, 운영자가 고른 목록과 사장님의 직접 발송으로 만드는 안.
3. **목록을 누가 채우는지.** 기본안에서는 운영자의 일이 된다. 처음 몇 개를 채울지.
4. **연락 제한.** 하루 5건, 만료 14일, 재연락 금지 30일.
5. **브랜드도 이 기능을 쓰는지.** 사장님만 쓰게 했다.

## 8. 만드는 사람에게 맡기는 것

- 테이블의 정확한 컬럼, 엔드포인트
- 초대 웹 페이지의 모양과 앱 설치로 이어지는 방식
- 운영자가 목록 파일을 올리는 방법(이번에는 서버에서 실행하는 스크립트면 충분하다)
