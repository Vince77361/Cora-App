# AI 제작 — 기능 설계

- 작성일: 2026-11-12
- 공통 규칙: `2026-11-11-collaboration-common-model.md`(2026-11-12 개정). 이 문서와 다르면 공통 규칙이 우선한다.
- 상태: 소유자가 별도 계획으로 떼는 것을 승인함 (2026-11-12). 문서의 **[제안]**은 소유자 확인 전이다.
- 실행 계획 순서: 기본은 6번(제작·검토·회고) 다음, 7번(포트폴리오·릴스·입찰) 앞이다. 코드가 기대는 것은 3번 계획과 가게 흐름 개정 계획뿐이라, 그 둘이 끝난 뒤면 앞당겨 실행할 수 있다.
- 캔버스의 F5 머리에는 "안" 표시가 붙어 있다(F4도 같다). 아직 확정 전인 화면이라는 뜻으로 읽었다. 앱에는 이 표시를 넣지 않는다 **[제안]**.
- 기획 화면: F5 Cora AI 제작 승인, A4 AI 콘텐츠 초안("가게 계정에 올리기"), A9 사장님 홈("이번 주 가게 게시물"), A2(체험단 후기 글), G1("영상 받기"), G3("가게 계정 게시물", "AI 게시물")

표기: **[결정]** 소유자가 정함 · **[화면]** 2026-11-12 기획 캔버스에서 확인됨 · **[제안]** 작성자의 추측이며 소유자 확인 전

## 1. 무엇을, 왜

사장님이 크리에이터 없이도 가게 계정에 올릴 게시물을 얻게 한다. 지금의 A4는 글과 장면 설명만 주는 초안이다. F5는 그 초안을 실제로 올릴 수 있는 결과물(카드뉴스 사진)로 만들어 주는 유료 주문이다.

- **[화면]** F5 위에 "Cora AI 제작 · 사람 크리에이터 아님"이라고 적혀 있다. 사람이 만든 콘텐츠와 섞이지 않게 하는 것이 이 화면의 첫 목적이다.
- **[화면]** G3는 체험단과 비교할 때 "가게 계정에 남은 것: AI 게시물 12개"를 Cora의 장점으로 든다.

### 하지 않는 것

- 가게의 인스타그램 계정에 Cora가 대신 올리는 것. "게시는 가게 계정에서 직접 해요."
- 영상(릴스) 만들기. 이번에는 카드뉴스만 만든다. 릴스 대본과 블로그 글은 지금처럼 글로 준다.
- 사람 크리에이터의 영상을 AI가 편집하는 것
- 실제 이미지 생성 (가짜 구현으로 시작한다. 실제 연동은 출시 준비 계획)

### 실패로 보는 것

- 사실과 다른 메뉴, 가격, 영업시간이 들어간 게시물을 사장님이 확인 없이 받는 것
- 가게가 쓸 권한이 없는 사진이 결과물에 들어가는 것
- AI가 만든 것이 사람 크리에이터의 콘텐츠처럼 보이는 것
- 결제했는데 결과물을 받지 못하는 것

## 2. 핵심 구조

```text
A4 초안(카드뉴스) ──"가게 계정에 올리기"──→ F5 제작 승인 ──"승인하고 주문"──→ 결제 ──→ 제작 ──→ 결과물 받기
        ▲                                     │
        └──────────"수정 요청"─────────────────┘ (초안을 고치거나 다시 만든다)
```

- **주문 한 건 = 초안 한 벌.** 주문은 그때의 초안 내용과 가게 정보를 사본으로 가진다.
- **돈은 보관하지 않는다.** 상대가 없는 구매이므로 결제하면 바로 Cora의 수익이다. 제작에 실패하면 전액 환불한다.

## 3. 화면별 동작

### F5 Cora AI 제작 승인

- **[화면]** 머리 "AI 제작". 표지 "Cora AI 제작 · 사람 크리에이터 아님". 제목 "카드뉴스 3장 · 초안 2".
- **[화면]** 줄: 사용한 자료("가게 페이지 · 확인한 사진 3장"), 게시 계정("한그릇 라멘 (가게 계정)"), 가격("[AI 제작 가격]").
- **[화면]** 확인 항목 세 개: "메뉴·가격·영업시간이 맞아요", "사진은 가게가 쓸 권한이 있어요", "게시는 가게 계정에서 직접 해요".
- **[화면]** 버튼 "수정 요청"(A4로), "승인하고 주문". 다 확인하지 않으면 "모두 확인해 주세요".
- 세 항목을 모두 확인해야 "승인하고 주문"이 켜진다. 확인한 시각을 주문에 저장한다.
- **[제안]** "확인한 사진"은 사장님이 이 주문에 쓰라고 고른 사진이다. F5에서 "사용한 자료" 줄을 누르면 사진을 고르는 화면이 열린다. 가게 대표 사진과 사장님이 새로 올린 사진(최대 5장, 각 5MB)에서 고른다. 링크에서 찾은 사진은 권한을 알 수 없으므로 쓰지 않는다.
- **[제안]** "초안 2"는 그 형식의 초안을 다시 만든 순번이다.
- **[제안]** 가격은 서버 설정 `AI_ORDER_PRICE`(원)이고 `GET /config`로 내려 준다. 값이 없으면 A4의 "가게 계정에 올리기"가 "준비 중이에요"로 가고 주문을 받지 않는다. 개발 환경의 예시 값은 `.env.example`에 둔다.
- **[제안]** "승인하고 주문"을 누르면 3번 계획의 결제창을 그대로 쓴다. 결제가 승인되면 사장님 홈으로 가고 "주문했어요. 다 만들면 알려드릴게요."를 보여 준다.

### 결과물 받기 (캔버스에 없는 화면)

- **[제안]** "AI 글" 탭에 "주문한 게시물" 목록을 더한다. 줄의 상태: "만드는 중", "다 만들었어요", "만들지 못했어요 · 환불했어요".
- **[제안]** 다 만든 주문을 누르면 카드 사진들과 본문 글이 보인다. "사진 저장"(휴대폰 사진첩에 저장), "본문 복사", "인스타그램 열기". 각 사진의 구석에 작게 "AI 제작" 표시를 넣는다(지울 수 없다).
- **[제안]** 결과물이 마음에 들지 않으면 "다시 만들기"를 주문당 한 번 할 수 있다. 추가 결제는 없다.

### A4 AI 콘텐츠 초안

- **[화면]** "가게 계정에 올리기"가 F5로 간다.
- **[제안]** 카드뉴스 탭에서만 F5로 간다. 릴스 대본과 블로그 글 탭에서는 버튼이 "본문 복사"다.

### A9 "이번 주 가게 게시물"

- **[화면]** "이번 주 가게 게시물 · AI 초안 2개 준비".
- **[제안]** 매주 월요일 9시(한국 시간)에 공개된 가게마다 카드뉴스 초안 두 벌을 새로 만든다. 지난주의 쓰지 않은 초안은 지운다. 주제는 가게 페이지의 꼬리표와 "손님들이 자주 한 말"에서 고른다.
- **[제안]** 실제 AI의 비용 때문에, 지난 30일 동안 앱을 열지 않은 가게는 건너뛴다.

### A2 체험단 후기 글

- **[화면]** "체험단 후기 글 · 선택 · 인스타 게시물로 바꿔 드려요".
- **[제안]** 후기 글 링크가 있는 가게는 초안을 만들 때 그 글의 내용을 재료로 쓴다. 글쓴이의 문장을 그대로 옮기지 않고 가게 정보(메뉴, 분위기)만 뽑아 쓴다. 후기 글의 사진은 쓰지 않는다(권한을 알 수 없다).

### G1 "영상 받기", G3의 두 줄

- 가게 흐름 개정 설계의 확인 항목 2번이 정해질 때까지 G1의 "영상 받기"는 게시 링크를 연다. 소유자가 AI 제작으로 잇기로 하면 그 협업의 가게로 A4를 연다.
- G3의 "가게 계정 게시물 {n}개"와 "AI 게시물 {n}개"는 석 달 동안 다 만든 주문의 수로 채운다.

## 4. 상태와 규칙

```text
PENDING_PAYMENT ──(결제 승인)──→ PAID ──→ RENDERING ──→ READY
       │                                      └──(3번 실패)──→ FAILED → 전액 환불
       └──(30분 안에 결제 없음)──→ 사라짐
```

- 제작은 작업 큐가 한다. 실패하면 세 번까지 다시 하고, 그래도 안 되면 `FAILED`로 바꾸고 전액 환불한 뒤 운영자에게 알린다.
- 주문은 가게의 주인만 만들고 읽는다.
- 장부: 결제 승인 때 `PG_수납` → `AI_제작_수익`. 환불 때는 3번 코드의 방식대로 `AI_제작_수익` → `가게_환급`. 계정 `AI_제작_수익`을 더한다(코드 이름은 3번의 `PG_IN`, `STORE_REFUND`에 맞춰 `AI_REVENUE`). 수수료는 따로 붙지 않는다. 주문의 장부는 "`PG_수납`에서 나간 합 = `AI_제작_수익` 잔액 + `가게_환급`으로 들어간 합"이 늘 맞아야 한다.
- F5에는 결제 수단을 고르는 곳이 없다. 카드로 고정한다 **[제안]**.
- 사진은 한 장 이상 골라야 주문할 수 있다 **[제안]**.
- "다시 만들기"가 세 번 실패하면 이전 결과물을 그대로 두고 다시 만들기 횟수를 돌려준다. 환불하지 않는다 **[제안]**.
- 결제 통지와 환불에는 3번 계획과 같은 중복 방지 키를 쓴다.
- 알림: "게시물을 다 만들었어요."(사장님), "게시물을 만들지 못했어요. 결제한 금액은 돌려드려요."(사장님) **[제안]**.

## 5. 데이터와 서버 (윤곽)

| 테이블 | 담는 것 |
|---|---|
| `ai_orders` (새로) | 가게, 초안 사본, 가게 정보 사본, 고른 사진, 확인 시각 세 개, 가격, 상태, 다시 만든 횟수 |
| `ai_order_assets` (새로) | 주문, 순서, 사진 경로 |
| `payments`, `ledger_entries`, `refunds` | 지금은 협업이 필수다. 협업 또는 주문 가운데 정확히 하나에 붙게 한다 |
| `users` | 마지막으로 앱을 연 시각 (주간 초안의 "30일 미접속" 판단) |
| `stores` | 대표 사진이 링크 분석에서 온 것인지 (그런 사진은 주문에 쓸 수 없다. 이미 있는 가게의 대표 사진은 쓸 수 없는 쪽으로 둔다) |
| `store_content_drafts` | 만든 주(주간 초안인지), 순번. 순번은 그 가게·형식 안의 번호이고 F5의 "초안 {n}"이다. 이미 있는 `version` 열과는 별개다 |

- 새 포트 `ContentRenderPort.render(draft, photos)` → 카드 사진들. 가짜 구현은 견본 사진 세 장에 초안의 글을 얹은 것처럼 보이는 고정 사진을 돌려준다. 환경변수 `CONTENT_RENDER_ADAPTER`.
- 작업 큐: 제작(결제 승인 직후), 주간 초안(매주 월요일 9시), 결제 없는 주문 지우기.
- 모듈 `ai-orders`를 새로 만든다. 결제는 `payments` 모듈의 공개된 서비스로 부르고, 내부 파일을 가져오지 않는다.

## 6. 소유자 확인이 필요한 것

1. **가격.** 캔버스에 `[AI 제작 가격]`으로 비어 있다. 주문당 정액인지, 월 구독인지도 정해야 한다. 지금은 주문당 정액으로 설계했다.
2. **만드는 범위.** 카드뉴스 사진만 만드는 것이 맞는지. 릴스 영상까지 만들려면 영상 생성 연동과 비용이 따로 든다.
3. **AI 제작 표시.** 결과물 사진에 "AI 제작" 표시를 넣는 것. AI 생성물 표시 의무와 인스타그램의 표시 정책을 실제 연동 전에 확인해야 한다.
4. **주간 초안.** 매주 두 벌을 자동으로 만드는 것이 맞는지. 실제 AI를 붙이면 가게 수만큼 비용이 든다.
5. **실제 생성 서비스.** 어느 이미지 생성 서비스를 쓸지는 출시 준비 계획에서 정한다.
6. **결과물과 주문용 사진의 저장 위치.** 지금의 사진 버킷은 공개 읽기다. 주문 결과물을 추측하기 어려운 공개 주소에 둘지, 비공개 버킷과 서명된 주소로 둘지 실행 전에 보안 기준(`security-baseline.md`)으로 정한다. **[제안]**은 비공개 버킷이다.
7. **주간 초안 두 벌을 A4에서 고르는 방법.** 캔버스 A4에는 두 벌을 오가는 곳이 없다. 계획은 "초안 1 / 초안 2" 알약을 넣었다.

## 7. 만드는 사람에게 맡기는 것

- 테이블의 정확한 컬럼, 엔드포인트 경로와 DTO
- 결과물 화면과 사진 고르기 화면의 배치
- `payments`가 협업과 주문을 함께 받는 방법
